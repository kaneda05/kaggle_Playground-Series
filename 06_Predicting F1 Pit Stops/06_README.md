# 🏎️ F1 Pit Stop Prediction (Playground Series - S6E5) コンペティション概要

**公式リンク:** [Kaggle Competition Page](https://www.kaggle.com/competitions/playground-series-s6e5)

## 🏆 目的 (Goal)
F1（フォーミュラ1）のレースデータを用いて、ドライバーが**「次のラップでピットインするかどうか（`PitNextLap`）」**を予測する二値分類タスクです。

## 📊 データセットについて (Dataset)
本コンペティションのデータは、「F1戦略データセット（F1 strategy dataset）」をベースに生成された**合成データ**です。

*   **データ特性:** 特徴量の分布はオリジナルに近いですが、完全に同一ではありません。
*   **意図的な変更点:** オリジナルデータに存在した `Normalized_TyreLife` という特徴量は、予測が簡単になりすぎる（答えが自明になってしまう）ため、意図的に除外されています。
*   **外部データの許可:** オリジナルのデータセットを外部データとして使用することが**許可・推奨**されています。オリジナルと合成データの違いを分析したり、学習に組み込んで精度向上を図ることがコンペの鍵となります。

## 📈 評価指標と提出形式 (Evaluation & Submission)
*   **予測対象:** テストデータセットの各 `id` に対して、ターゲット変数 `PitNextLap` が1（ピットインする）となる**確率**を予測します。
*   **提出フォーマット:** ヘッダー行を含み、`id` と `PitNextLap` の2つの列を持つCSVファイル形式で提出します。

## 🚀 コア戦略と実装内容 (Key Strategies)

単なるベースラインから脱却し、上位陣（Top 10%圏内）に食い込むために、以下の4つの高度なアプローチを実装しました。

### 1. 外部データの統合 (External Data Integration)
コンペティション提供の合成データ（約43万件）に対し、ベースとなった「F1 Strategy Dataset（約10万件）」を外部データとして結合。コンペ用データから意図的に削除されたカラムを揃えることで、モデルの汎化性能を大幅に向上させました。

### 2. ドライバー戦略特徴量の導入 (Driver Strategy Features)
物理的なタイヤの摩耗（Degradation）だけでなく、F1のドメイン知識を活かした**「マクロな戦略コンテキスト」**を特徴量化しました。
*   `Driver_Avg_Stint_Length`: そのドライバーの平均的なピットイン間隔（引っ張るタイプか否か）。
*   `Race_Compound_Life_Ratio`: そのレース・そのタイヤにおける限界周回数に対する現在の割合。
*   `LapTime_Driver_ZScore`: 自身の平均ラップタイムからの相対的な遅れ（Zスコア）。

### 3. 多様性のあるモデル構成 (Diverse Ensemble Modeling)
決定木ベースのモデル同士の相関が高まる問題を解決するため、テーブルデータ向けディープラーニングモデルを導入しました。
*   **Tree Models:** LightGBM, XGBoost, CatBoost
*   **Deep Learning:** **RealMLP (via PyTabKit)**
これにより、決定木が捉えきれない非線形な関係性をニューラルネットワークが補完する強力なアンサンブルを実現しました。

### 4. Nelder-Mead法による重み最適化 (Weight Optimization)
4つのモデルのOOF（Out-of-Fold）予測値を単純平均するのではなく、`scipy.optimize.minimize`（Nelder-Mead法）を用いて、**AUCが最大化される最適な重み係数を数理的に探索・適用**しました。

## 🧠 学んだこと・技術的知見 (Lessons Learned)

本プロジェクトを通じて、Kaggleにおけるテーブルデータ分析のベストプラクティスを数多く学びました。

1. **アンサンブルにおける「多様性」の重要性**
   XGBoostやLightGBMのハイパーパラメータを微調整するよりも、全くアーキテクチャの異なるモデル（今回であればPyTabKitによるRealMLP）を1つ追加するほうが、アンサンブルによるスコアの伸び（ブレイクスルー）が圧倒的に大きいことを実感しました。

2. **CatBoostのパラメータトラップと対処**
   CatBoostにおいて `subsample` を指定して学習させようとした際、デフォルトのデータ抽出手法が `Bayesian` であるためエラーが発生しました。これを回避するために `bootstrap_type='Bernoulli'` を明示的に設定する必要があるという、ライブラリ特有の仕様を学びました。

3. **ドメイン知識に基づくアグリゲーション（GroupBy）の威力**
   「ラップタイムが80秒」という単一の数値ではなく、「そのドライバーの平均と比べて遅いのか？」という文脈（Context）をGroupByで作成することが、決定木モデルの精度を飛躍させる鍵でした。

4. **Kaggleコミュニティにおける「魅せる」Notebookの構築**
   NotebookでUpvoteを集めるために、単にコードを書くだけでなく、UI（Markdownの装飾）や目次の整備、そして何より**「参考にさせていただいた他者のNotebookへの謝辞（Credits & Acknowledgements）」**を記載する重要性と文化を学びました。
